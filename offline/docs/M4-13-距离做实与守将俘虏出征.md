# M4-13 距离做实 / 兵种适性 / 守将与俘虏 / 出征连贯

> 用户 2026-11-15 反馈：「检查战斗系统中的兵种适性、战法机制，现在的战法有距离这个规则，
> 但是游戏战斗中没有体现出这个距离的意义，要么去掉距离机制，要么战斗中加入这个距离机制；
> 占领城市后如果抓捕了敌方武将没有招降机制，敌方将领一直都是十常侍，换个城市攻打又会碰到
> 十常侍，武将严重重复；出征流程用起来很不方便，出征界面设计的不连贯。」
> 已确认的决策：**保留距离并做实**（不删规则），兵种适性一并接进战斗结算。

---

## 一、先纠正一个判断：距离不是没实现

内核链路原本就是通的：

```
conf/skills-range.json + 各表 ui.range
 → server/skills.js rangeOf() / attackDistanceOf()
 → server/battle.js makeUnit() 注入 pos / attack_range；kernelSkillAt() 注入 Effect.range
 → offline/kernel/engine.js  slotDist() / nearestFoe() / effectTargets()  ← 真的参与判定
```

`slotDist` 跨阵营取 `pos 和 + 1`（1~5），普攻超 `attack_range` 打不出，战法按 `effect.range`
先过滤再截前 N 个，已有 4 组内核单测 + p6 / p7 单测锁死。

**真正缺的是「看得见」和「能决策」**：战报、推演、编队都不显示距离判定结果；
`pos` 硬绑定编队槽位且 UI 没讲清；全表 176 条战法里 68 条是「无距离限制」的 9。
所以玩家体感「规则写了、战斗里没有」是准确的。

另外查实：`Hero.hit_range` 在内核结算层被丢弃（`battle.js` 写死 1，内核全文不读），
距离语义改挂在 `UnitInput.attack_range` + `Effect.range` 上；追击战法不吃射程表；
`conf/skills.json` 的 `ui.range` 会被 `applyRangeNote()` 用推导值覆盖，改它不改变战斗结果。

**没有改射程数值**：`build-innate-skills.mjs` 的攻击型战法射程本来就取自率土官网
`distance` 并钳到 1~5，9 只给治疗/增益/指挥/追击。强行压数值会破坏 M4-9 的史实证据
忠实度与既有单测。做实的方向改为「可观测 + 可决策 + 同源」。

## 二、距离做实（四项）

| 改动 | 文件 | 说明 |
|---|---|---|
| 内核产出 `range_trace[]` | `battle-core/src/types.ts` / `engine.ts`；编译同步 `offline/kernel/{engine.js,engine.d.ts,types.d.ts}` | 普攻超距打空、战法射程筛掉目标时记一条轨迹，含 `range/nearest/reachable/total/out_of_range`。**不进 `events`**，因此 `event_fingerprint` 与黄金向量逐字节不变；常规战斗轨迹为空 |
| 战报讲人话 | `server/battle.js buildBattleAnim()` | 战法追加「有效距离 R · 仅及 M/N 名敌军（最近相隔 X 格）」；普攻打空补一句「列于大营，攻距 3，最近敌军相隔 5 格——弓矢不及，本回合未能出手」 |
| 出征页可决策 | `server/skills.js warGoPanel()` | 新增「站位 · 射程 · 适性」卡片，逐槽显示战位、适性%、攻距、可及敌位；写明跨阵营距离公式与配将建议 |
| 口径纪律 | 单测 `m4-13-…test.js` | 超距打空有轨迹 / 射程筛人有轨迹 / 无约束时轨迹为空且事件指纹不变 / 战报与适性接线静态闸 |

**兵种适性**（过去只是界面百分比）：抽成零依赖叶子 `server/domain/aptitude.js`，
`city-econ.js` 改为 re-export（展示层 import 路径不变），`battle.js makeUnit()` 用同一个
`armsApt()` 把 1.00~1.15 系数乘进 `attack_base` / `defence_base`，clamp 100 守住
M4-10 的「能力上限 100」红线。**只动攻防、不动速度/智力**——速度会改 `actionOrder`，
进而漂事件指纹。`panels-ui.js` 的「武将适性影响属性发挥」假文案改为如实描述。

## 三、守将不再重复

根因：`conf/json/npc/npc_army.json` 全表只有 `100002~100006` 六个 cfgId，
8 个等级里 7 个的 `army[0]` 都是 `[100002,100003,100004]`，`army[1]` 从未被消费；
`defenseFor()` / `makeDefenders()` 写死取 `army[0]`，守将选择跟城池/坐标/势力/seed 全无关系。
1 级城只有 1 个守将，恰好是 `100002 = 十常士`（内核 `hero_names` 写作「十常侍」）。

- 新增 `server/domain/garrison.js`：FNV 哈希 `(cityId, owner, level)` 从**客户端可见的
  368 位原版武将**里确定性取 1~3 人，质数步长 37、同城三人不相邻、跨城起点分散；
  势力 `startGenerals` 排池前段；排除玩家已拥有/已在押/主角/代将。
- `npc_army.json` 降级为兵力与等级配置，不再提供 cfgIds。
- `defenseFor()` 的三个调用点（正式结算 / 推演 / NPC 来犯）**都传同一个 state**，
  保证排除名单同源——本轮真实踩过「推演 600 折损 vs 正式 594」的坑，根因就是推演没传 state。

**本轮验收抓到的真回归（必须记牢）**：首版守将池直接用 `cfg.generalByCfg` 全表 505 位，
冒烟在 `(city[0].x, city[0].y+1)` 取到了 `240091 杨阜` / `240128 韩浩` —— 这两位是
`heroes-240.json` 追加进服务端配置表的，原版客户端（`web/` 逐字节不可改）打包的只有
`general.json` 的 `100001~100593`。`WarReportItemLogic.setTeams → GeneralItemLogic.updateView`
按 cfgId 查表拿到 `null`，抛 `Cannot read properties of null (reading 'name')`，
战报列表和详情双双打不开，双态冒烟 33 项里红 4 项。

修法不是压数字范围，而是**配置层给权威准入**：`config.js` 在并入主角与 heroes-240
**之前**对原表 cfgId 取快照，导出 `cfg.clientGeneralIds`；`garrisonPool()` 只认这个集合
（轻量测试桩没带集合时退化为「非追加条目」启发式）。守将、俘虏都回填进原版战报，
所以一律走这个准入。新增回归单测锁死 `makeDefenders()` 在冒烟坐标下不产出不可见 cfgId。

## 四、俘虏链路闭环

根因不是公式或执行函数缺失（`captive-rules.js` / `recruitCaptive()` 都在），而是：

1. **两条占领路径只有一条落库**：常规 WS 路径 `army.assign → battle_arrive →
   handlers.processTask` 占的是地图格，完全不写 `state.captives`；只有战略层占城写，
   还要过 `roll = (候选字符串长度×31 + 天数×7 + 兵力) % 100 < 30` 这种与战果无关的怪判定。
2. 招降只走 HTTP、唯一按钮藏在六府「武将」页二级面板，占城后没有即时提示。
3. 没有释放 / 处斩，俘虏只能等越狱。

改动：

- 新增 `server/domain/captives.js`：`captureFromBattle()` 按**歼敌比**确定性判定
  （全歼必俘、惨胜六成），同源给两条占领路径；`releaseCaptive()` / `executeCaptive()`
  提供放归与处斩（处斩记一笔 `role.infamy`）。
- `handlers.js processTask` 胜利分支接入；`strategy.js settleArmyBattle` 改调同一函数。
- `index.js` 增加 `captiveRelease` / `captiveExecute` 动作；`panels-ui.js` 俘虏名册
  同屏给「招降 / 放归 / 处斩」三个按钮。
- `skills.js` 确认开战后即时 toast 告知「阵前擒得敌将，可在六府武将页招降／放归／处斩」。

**2026-11-16 补充（处置后果闭环）**：初版 `role.infamy` 只写不读，放归完全没有后果，
与 PRD R-21.5 / GDD §7.3 不符。现新增零依赖叶子 `captive-reputation.js` 统一口径：
放归 `st.fame+=2`、处斩 `st.fame-=2 + infamy+=1`；名望经 `defectRateWithFame()`
进入 `defectTick` 的慕名来投率（封顶 40 点防刷）；态度后果经 `diplomacy.js
adjustAttitudeByEvent()` 落 `eventAdj`——放归 −5、处斩 −15 且董卓（`sili`）豁免
（GDD §7.3 / §5.9 原文）。战报不带原属势力，故态度对所有 NPC 势力生效，
不定向到单一势力——这是已知简化，登记在 SDD §17.9 `DEV-30`。

## 五、出征流程连贯

P11 把「抵城自动结算」改成「挂起等确认」后，领域层与协议层都闭环了，
但 UI 层只加了两个页签，断点全在 `skills.js`：

| 断点 | 修法 |
|---|---|
| 抵达挂起后零提示、零自动跳页（`pendingBattles` 全书只读一次做角标） | `refresh()` 状态驱动：0→N 时 toast + 出征窗自动切「③ 遭遇」；沙盘 dock 常驻 `出征 ● N` 角标 |
| 所有入口硬编码 `tab:'go'`，有仗要打也被拉回「① 集结」 | 7 处入口去掉硬编码；`__slgWarWindow` 按待办智能落页（有遭遇→遭遇、有消化→消化、否则集结） |
| 每次 `makeWindow` 全量删建 DOM，选一次队伍/目标就滚回顶部 | `scrollSlot` 支持 `'war'` key，`renderWar` 在重绘边界 `scrollRemember('war')` / `scrollApply('war')` |
| 确认开战后一律跳「战报」，攻城只靠一句 toast 提示去消化页 | 按结果落页：占城且有 digest 直接进「④ 消化」，否则进战报 |
| 队列页仍是 P11 前旧规格「已抵城下 / 当天结算 / 撤不回来」，撤回按钮点了必报 `already_arrived` | 待决行显示「已抵城下 · 待主公定夺」、禁用批量撤回、把「撤回」换成「去遭遇定夺」 |
| `pendingBattle` 无 TTL，队伍可永久锁死 | 超过 3 旬（30 游戏日）未定夺自动 `strategyRetreatBattle()` 班师解锁 |
| GDD / P8 规格与实现相反 | GDD 六门表 ② 行、P8 撤回规格同步为确认制 |

## 六、验收

- 单测 **483/483**（新增 12 条 M4-13 回归，含客户端可见守将回归）；battle-core 内核单测 **37/37**，黄金向量未漂。
- 全量发布闸见 `tools/check-release.js`；报告新鲜度闸会要求重跑双态冒烟 / UI 审计 /
  真鼠标 / perf / layout 后再打包核查。
- `web/` 逐字节不可改（指纹 `ee987ec2…`），UI 一律运行时注入。

## 七、长期纪律

1. **距离轨迹绝不进 `events`**：`event_fingerprint = hash16(stableStringify(events))`，
   M4-7 已有「事件 payload 加字段会漂黄金向量」的教训。
2. **推演与正式结算必须传同一个 state**：任何进入守将分配的易变输入（俘虏、已拥有武将）
   都要同源，否则 `A1 预演==结算` 会立刻报红。
3. **适性唯一权威是 `domain/aptitude.js`**：展示与战斗共用 `armsApt()`，不许再出现第二套口径。
4. 改 `battle-core/src/*.ts` 后必须 `npm run build` 并同步 `offline/kernel/`。
5. **凡是要回填进原版战报的武将，cfgId 必须落在 `cfg.clientGeneralIds` 内**：
   `generalByCfg` 是服务端全表（505 位），原版客户端只认 368 位原表武将；
   新增武将可以进面板/编队（注入 UI 自己渲染），但守将、俘虏这类会进 `warReport.push`
   的角色不能越界，否则原版战报 UI 查表为 `null` 直接抛异常。
6. **改完 `server/` / `conf/` 必须重打包再跑双态冒烟**：打包态报告验的是旧包，
   只跑源码态会形成「源码已修、发行包仍崩」的假绿。
