# 合规与换皮清单（U26）

> 目的：把「哪些东西是别人的、发行前必须换掉」写死成可核对的台账，而不是留在口头约定里。
> 台账本体：`offline/conf/compliance/provenance.json`
> 核查工具：`node offline/tools/compliance-report.js`（产物 `offline/reports/compliance.json`）
> 发行核查：`node offline/tools/check-release.js` 已把「台账覆盖」与「无 IL 夹带」纳入 70+ 项检查。

## 1. 结论先说

- **代码层面干净**：仓库内没有 `.dll/.pdb/.il`，也没有 `完整原始版 / export/ / 反汇编 / decompiled` 路径；打包产物 `resources/app` 1731 个文件扫描 0 命中。
- **数据与画面不干净**：4 类资产属于「复制自第三方、当前无授权」，商业发行前必须换皮或取得授权。其中 `offline/web/`（1582 文件的画面与 UI）优先级最高。
- battle-core 的 README 早就写明「`battle-kit/export/完整原始版/` 的 IL 与内部类结构不得随包分发」；本清单把它变成了机器可校验的规则。

## 2. 必须替换的资产（derived_unlicensed）

| 资产 | 内容 | 规模 | 换皮动作 |
|---|---|---|---|
| `offline/web/` | 原客户端 web-desktop 画面 / UI / 地图 / 建筑 | 1582 文件 | 整体替换或取得授权。**这是唯一无法靠改名解决的**，需要重做美术与 Cocos 资源 |
| `offline/conf/skills.json` | 战法名录与等级数值 | 31 条 | 换名 + 重做数值；完成后同步 `skills-range.json` 与 `conf/campaign/skill-source.json` |
| `offline/conf/library-skills.json` | 六府战法图鉴（按展示重排） | 20 条 | 随上表一并替换 |
| `battle-core/config/battle_config.json` | 83 伤害率 / 58 等级插值 / 188 效果术语 | 83 条 | 重做数值后重跑 `npm run golden`，并更新配置指纹 `f186e15d0c1f266b` 的声明处 |

替换顺序建议：**先数值后画面**。数值换完能立刻重跑单测与黄金向量确认内核没坏；画面换完必须重做 `web/` 指纹登记与冒烟。

## 4. 工具怎么用

```bash
cd offline
node tools/compliance-report.js          # 人读摘要；有问题退出码 1
node tools/compliance-report.js --json   # 全量 JSON
node tools/check-release.js              # 发行核查（含本项）
```

工具做三件事：

1. **覆盖性**：台账登记的文件必须存在；仓库里出现「疑似第三方派生」但没登记的，直接判缺口（防止以后偷偷又复制一份进来）。
2. **禁入物**：按台账 `forbidden_artifacts` 扫扩展名与路径片段，命中即失败。
3. **发行包**：`build/SLG-Offline-win32-x64/resources/app` 存在时同样扫一遍。

## 5. 已知限制（诚实标注）

- 只有「扩展名 + 路径关键词」能自动查；**内容是第三方的衍生数据无法自动识别**（例如把战法数值改两个百分点）。这类只能靠台账 + 人工复核。
- 台账里的 `count` 是登记时的规模，换皮后需要手工更新；工具不校验数量一致性，只校验存在性。
- `offline/web/` 按目录登记，不逐文件列 1582 条；只校验目录存在与指纹（指纹校验在 `check-release.js` 的原有项里）。
