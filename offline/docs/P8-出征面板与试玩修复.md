- 前置：P7 城市纵深与战法距离（`ca6a4ff`）
- 配套：`tests/p8-war-panel.test.js`（10 项）、`electron/smoke.cjs` 出征面板自检

## 一、为什么要做「出征面板」

改动前，出征只是**城池概览页最底下的一个块**：

1. 得先在沙盘上准确点到目标城，再滚到底；
2. 只能按「全城三支队兵力之和 × 比例」出兵，服务端却只挑兵力最多的一支，
   确认框写「约 1900 人」、实际只有 800 人上场；
3. 出发地只能是「与目标相邻的己方城」，多城时用一个下拉硬塞；
4. 出发之后没有任何地方能看队列、改主意、撤回。

更糟的是两层实现缺陷让这个块**根本不显示**：

- `#slgUIv2 .win` 样式默认 `display:none`，注释说「由调用方打开」，
  但 `makeWindow()` 从未设置过 `display` —— 城池面板一直存在、可读 textContent，
  却不可见。玩家点城池只看到左上角的小浮层，自然认为「没有内政/出征面板」。
- 城池面板所在 IIFE 没有定义 `esc()`，而渲染代码到处调用它。
  一旦渲染到含 `esc` 的段落就抛 `ReferenceError`，异常被 Promise 的 catch 吞掉，
  页签只画一半 —— 概览页的出征块正好排在后面，于是永远不出现。

P8 把这两处修掉，并把出征升级成独立面板。

## 二、面板结构

入口三处，都指向同一个 `window.__slgWarWindow()`：

| 入口 | 位置 |
|---|---|
| 沙盘顶部工具条 | 「出征」按钮（推演一月旁） |
| 六府 | 左侧导航「出征 · 选城选队列兵」 |
| 城池面板 | 概览页「出征 XX」卡 / 己方城「自本城出征」按钮 |

### 出击页

```text
出发城  [安邑（3 队 / 2400 兵 · 粮 2000）▾]
        驻城兵力 2400 · 城防守军 1796 · 城库存粮 2000 · 可派队伍 3 支

可派队伍
  队伍#1  盾 600 / 弓 300 / 骑 200  合计 1100 兵 · 队速 128   [已选]
          关羽（盾步适性 106%）、张飞（骑兵适性 98%）
  队伍#2  ...                                                [点选]

可攻目标
  黎阳  兖州·袁绍·守军约 1982   程 179 里 · 预计 4 日 · 兵力偏少   [已选]
  邺城  冀州·袁绍·守军约 1076   程 151 里 · 预计 3 日 · 胜负参半   [点选]

出兵概览
  队伍#1 共 1100 兵，本役实出 1100 兵，留守 0。
  出兵比例 [全军][半军][三成]
  行军：程 179 里 · 队速 128 · 预计 4 日抵达（约第 12 日）· 行军粮 110
  目标守军约 1982  兵力偏少，建议先增兵或换小城
  [出征 黎阳]
```

规则：

- **人数口径唯一**：`实出 = round(所选队伍兵力 × 比例)`，粮草 `ceil(实出 × 0.1)`。
  界面、确认框、服务端结算、行军记录四处的数一致。
- 无队伍时列出其它己方城的可派队伍，一键「以此为出发城」；
  全军无兵时给「去本城征兵」直接跳到该城征兵页。
- 行军日数 `ceil(里程 ÷ (55 × 队速/100))`，队速取队内最慢武将，夹 1~40 日。

### 行军队列页

```text
队伍#1  安邑 → 黎阳
程 179 里 · 第 8 日发 → 第 12 日到 · 余 2 日（50%） · 兵 1100 · 耗粮 110   [撤回]
```

- 攻击队撤回：解锁队伍、退回出发城、行军粮退一半；
- 辎重队撤回：粮车折返，八成回府库（两成路上损耗）；
- 已到城下（`today >= arriveDay`）不可撤 —— 当天就要结算，避免「撤回」抢先洗掉战斗结果。

### 战报页

近期军报（攻陷 / 失利 / 相持 / 出征 / 折返）+ 俘虏提示。

## 三、协议与领域层

| 层 | 变更 |
|---|---|
| `strategyAttack` | `frac` 参与实际兵力与粮草计算；返回 `armyId / troops / deploy / frac / supplyStops` |
| `strategyRecallMarch` | 新增。校验 `no_march` / `already_arrived`，解锁归城、按类型退粮 |
| `marchableFrom(cityId, state?)` | 传 `state` 时过滤己方城与自身 |
| `strategyViewState` | `marches` 增 `armyId/troops/fromName/toName/remainDays/progress/grainCost/recalled`；玩家城增 `troopSum/armsCount/investDays`；`population` 统一取经济层 |
| HTTP `/__slg/strategy/action` | 新增 `attack` / `recall` 动作 |
| WS `strategy.recallMarch` | 新增协议分支 |

## 四、试玩 22 项的处理

| 编号 | 问题 | 处理 |
|---|---|---|
| 1 | 任意城都能编队 | `army.dispose` 校 `isOwnCity`，不存在/敌方城回 `not_own_city` |
| 2 | 行军中可改编/征兵 | 两处加 `army.marchId` 判断，回 `marching` |
| 3 | 编队不校武将存在 | `findGeneral` 找不到回 `bad_general` |
| 4 | 己方城也出现「攻打」 | `marchableFrom(..., state)` 过滤己方城；概览只给情报与入口 |
| 5 | 出征人数与实出不符 | 按所选队伍 × 比例计算，按钮与结算同源 |
| 6 | 非主城无设施 | 设施键改为 `s<战略城id>`，举义逐城建一套，占新城懒建 |
| 7 | 可升级敌方城设施 | `city.upFacility` 校 `isOwnCity` |
| 8 | 征收不认城 | 按 `cityId` 取城，金产用该城 `cityYield`，次数/CD 逐城独立 |
| 9 | 升级失败无 msg | `max_level` / `upgrading` / `no_such_facility` / `res_not_enough` |
| 10 | 转换失败无 msg | `no_market` + 提示文案 |
| 11 | 征收超次无 msg | `times_limit` / `cooldown`（带 `waitSec`） |
| 12 | 五项内政共享冷却 | 改 `investDays[kind]` 按项记，UI 置灰并显示「第 N 日可再办」 |
| 13 | 运输起点写死首都 | 起点下拉弹窗，传 `fromCityId` |
| 14 | 出征两套失败语义 | `ok` 为唯一判定，`code` 同步非 0 |
| 15 | 相邻与可出征不同源 | 「相邻城池」行加 `marchable` 判定，受阻标「行军受阻」 |
| 16 | 驻军是静态地图值 | 玩家城分列「驻城兵力（部队合计）」与「城防（守军）」 |
| 17 | 行军上限 12 日 | 放宽到 40 日，长途另给「途中休整」提示 |
| 18 | 人口双字段 | 视图只取经济层 `pop` |
| 19 | 密码明文进存档 | 只存 `passHash`（sha256 截断），响应不回传 |
| 20 | 异常被吞成成功 | `onMessage` catch 回 `code 500 + reason: internal` |
| 21 | `state.citys` 只有 1 条 | 设施/征收不再依赖它；本地城只作客户端 UI 载体 |
| 22 | 未知消息回 0 | 回 `404 + unknown_message` |

### 额外发现的三个必崩点

1. **城池面板不可见**（`display:none` 无人打开）——「没有出征/内政面板」的根因；
2. **`esc is not defined`** —— 城池面板 IIFE 缺定义，页签渲染中断；
3. **`city.facilities` 收到 `cityId: 0`** —— 原客户端 `qryCityFacilities()` 默认传 0，
   `Number(m.cityId ?? ...)` 让 0 漏过去，回了不存在的城，客户端 `getMyCityById(0)`
   拿 null 后读 `.cityId` 直接抛异常（冒烟从 26/26 掉到 0 的就是这一条）。
   现在 0 视为未指定，并用「双 id」兼容原客户端：
   `cityId` 永远是客户端自己的城，`realCityId` 才表示要操作的战略城。
