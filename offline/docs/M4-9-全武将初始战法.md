# M4-9 全武将初始战法 + 点名武将属性回落

> 玩家原话：「检索游戏所有武将，参考率土之滨武将技能效果，把所有武将的初始战法都按照率土之滨的武将效果进行初始化技能配置。修改主角、夏侯惇、黄盖属性，这三位属性值比其他武将高出太多。」
>
> 本文记录这批改动**怎么做的、凭什么这么做、边界在哪、怎么回归**。玩法数值如有冲突，仍以 `docs/GDD-顶配详细设计.md` 为准；本文是这批的变更与证据说明。

---

## 1. 改之前是什么状态（先量，不动手）

| 项 | 改前 | 改后 |
|---|---:|---:|
| 有初始战法的武将（`conf/campaign/hero-skills.json`） | 57 位 | **424 位（100%）** |
| 运行时战法表条数（`SKILLS`） | 81 | **177**（81 + 96 条新增） |
| 新增战法 cfgId 段 | — | 920000 起（920001~920095） |
| 武将进战场后初始战法为空 | 其余 363 位恒为 `null` | 0 位 |

改前的问题不是「战法太少」而是**大半武将根本没有初始战法**：`skills[0]` 恒为 `null`，玩家抽到谁都是白板，率土那套「每人一个自带战法」的辨识度完全不存在。

## 2. 数据从哪来、怎么判可信（证据分级）

**唯一数值来源**：率土之滨官网战法表 `battle-kit/skill-library/source/raw/stzb_skill_extra.json`（648 条记录，642 条有效）。这是 W0（一手官网）级证据，**不读** `adapted/full_mapping_stzb.json` 的自动推断结果——它是 E2，曾把「银龙冲阵」（官网标签是攻击伤害）误翻成谋略伤害，直接导致「赵云打策略伤害」这种一眼假配置。

三条判别口径，全部可复算：

1. **自带 vs 可学习**：`disassembleHero1/2/3` 全空 = 该战法在官网没有拆解出处，即「自带战法」，只属于某个具体武将；有拆解出处的是通用战法，可以给任何人。改前用 `disassembleHero` 做效果匹配，结果「苦肉计」发给 14 个不相干的人（丁夫人、刘度…）、「奋疾先登」判给赵云、「当阳桥」发给兀突骨——**表面人人有战法，本质全是错的**。
2. **伤害类型**：只认官网 `effect` 标签 + `desc(level1)` 句式。「攻击伤害」→ `PHYSICAL_DAMAGE`，「策略攻击伤害」→ `STRATEGY_DAMAGE`，两者不能靠名字猜。
3. **专属归属**：真人专属战法只给核实过的本人，其余武将只能从通用池按定位取。归属证据逐条写在 `conf/campaign/innate-skill-overrides.json`（附来源 URL/公告日期），本作未收录的武将保留在 `candidates_rejected` 里备查。

**当前证据分布**（`conf/campaign/innate-skill-audit.json` 的 `totals`）：

| 档位 | 人数 | 含义 |
|---|---:|---|
| `w0Linked` | 139 | 官网表里能直接对上该武将的战法（强证据） |
| `derived` | 237 | 官网无该武将出处，按五维定位匹配同效果范式的通用战法（**不是该武将的自带战法**） |
| `authored` | 1 | 主角专属（`19001 后世之识`，本作原创） |

> ⚠️ 审计表 `caveat` 已写明：官网只公开「拆解/传承出处」，**没有**「武将 → 自带战法」的逐人对照表。要消灭那 237 条派生，必须引入外部逐人对照数据源（且涉版权），不是靠再跑一遍脚本能解决的。这条局限写在数据里，不藏在文档里。

## 3. 424 位怎么压成 96 条战法（效果范式去重）

系统不可能为 424 人写 424 条互不相同的战法——玩家也记不住。做法是按**效果范式**去重：

```
signature = 战法类型 | 各槽 effect_type 串联 | 目标带宽(single/group/all) | 首槽增益词或控制状态
```

- 642 条有效战法 → 227 个不同范式 → 取每个范式里「官网星最高、五维和最高」的那条做代表 → **96 条**代表战法；
- 同一范式的其他武将直接复用代表战法的 cfgId（`ui.limit` 记录被多少人共用，供 UI 展示「可学习人数」）；
- 战法描述模板里的 `%n%` 占位符个数 = 内核结算槽数，Lv10 = Lv1 × 2，目标类型与客户端 `ui.target` 一一对应——这三条都是硬校验（见 §6）。

**定位分流**（决定从哪个池抽）：`roleOf` 按五维最大值判 CONTROL / OUTPUT / DEFENSE / BUFF，四个池子各自独立，避免「许褚从增益池抽到军师战法」这类错配（该 bug 的真实成因是 `defense 9200 > force 9100` 被判成 BUFF，比较方向写反了）。

## 4. 三人属性回落（玩家点名的三个）

改前三人**并非全表最高**（全表 505 条口径）：

| 武将 | 五维和 | 全表排名 | 同星级位置 |
|---|---:|---:|---|
| 主公 880001 | 32,200 | 163/505 | 4★ 上四分位 |
| 夏侯惇 100449（5★） | 36,100 | 55/505 | 5★ 上四分位 |
| 夏侯惇 100079（4★） | 35,900 | 64/505 | **超过 5★ 中位** |
| 黄盖 100162（4★） | 33,500 | 120/505 | **超过 5★ 中位** |
| 黄盖 100587（5★） | 32,300 | 158/505 | 5★ 中位以下 |

所以玩家感受到的「高出太多」有两条真实成因，不是单纯的数字大：

1. **成长率偏高**：夏侯惇 4★ 成长和 359 是同星 p94，等级一拉开就跟同星武将明显脱节——玩家体感是「越练越离谱」；
2. **同名多版本倒挂**：黄盖 4★（33,500）比 5★（32,300）还高，夏侯惇 4★（35,900）几乎追平 5★（36,100），**稀有度彻底失去意义**。

**修法**（`tools/normalize-hero-stats.mjs`，确定性、幂等、带 `--dry`）：

- 以「同星级五维和中位 × 0.92」为上限，**等比缩放**五维（保留各维人设比例，不做削平）；
- 成长率同样取 `min(现值, 同星中位 × 0.92)`，**只降不升**；
- 同名多版本按（星级降序）强制单调，低星 ≤ 前一档 × 0.94——倒挂从结构上不可能再出现；
- 主角只改 `conf/campaign/protagonist.json`（M4-8 之后战斗/内政/外交/行军统一由 `gameStatOf` 读它，改一处即四处同源）。

**结果**：

| 武将 | 五维和 | 成长和 |
|---|---|---|
| 主公 880001 | 32,200 → **28,300** | 180 → 180（同星 p3，本就偏低，不动） |
| 夏侯惇 5★ 100449 | 36,100 → **32,100** | 379 → **312** |
| 夏侯惇 4★ 100079 | 35,900 → **28,300** | 359 → **265** |
| 黄盖 5★ 100587 | 32,300 → **32,100** | 239 → 239 |
| 黄盖 4★ 100162 | 33,500 → **28,300** | — |
| 黄盖 4★ 100439 | 30,800 → **26,600** | — |

> 调音旋钮：嫌名将手感偏弱，只改 `normalize-hero-stats.mjs` 里的 `0.92`（0.92→1.00 即「落在同星中位」），然后重跑本脚本 + `build-innate-skills.mjs`，不要手改配置。

## 5. 文件边界（和并行工作线互不覆盖）

| 文件 | 谁写 | 说明 |
|---|---|---|
| `conf/innate-skills.json` | `tools/build-innate-skills.mjs` | 96 条新增战法（920000+），运行时由 `server/skills.js` 挂进 `SKILLS` |
| `conf/campaign/hero-skills.json` | **只由** `build-innate-skills.mjs` 写 | 424 位映射 |
| `conf/campaign/innate-skill-overrides.json` | 人工维护 | 专属归属证据表 |
| `conf/campaign/innate-skill-audit.json` | `build-innate-skills.mjs` | 逐人审计，`problems` 必须为 0 |
| `conf/json/general/general.json`、`conf/campaign/protagonist.json` | `normalize-hero-stats.mjs` | 只打数值补丁，保留原字节格式（TAB+CRLF），diff 不炸 |
| `server/domain/general-stat.js` 等 | **M4-8 工作线** | 本批不碰：那是「史实五维 → 战斗数值」的派生层，本批改的是配置原值 |

**已堵掉的坑**：`tools/build-library-skills.js` 原来会无条件回写 `hero-skills.json`（它手里只有 `hero_skill_map.csv` 的 51 人 A2 推荐适配）。任何人为了重新生成 `library-skills.json` 跑一次那个脚本，就会把 424 人的表**静默覆盖成 51 人**，玩家侧表现是「大半武将初始战法又变空」。现在默认不写，要写得显式加 `--force-hero-map`，并在输出里警告覆盖范围。

## 6. 防退化（改错了会立刻红）

`tests/innate-skills-and-stats.test.js` 5 条：

1. **每位武将都有初始战法**，且映射指向真实存在的战法（无悬挂 id）；审计表人数 = 武将名单人数；`w0Linked > 100` 防「退化成随机分配」。
2. **描述占位 / 等级成长 / 目标 / 内核槽一一对应**：`%n%` 个数 = `effect_value.length` = `kernel.effects.length`，Lv10 = 2×Lv1，`rangeOf(s) === s.ui.range`（描述写「有效距离 2」内核就必须是 2），不得与包内原有战法重名。
3. **点名武将属性回落 + 同名单调**：不超过同星 p75，低星不反超高星，审计表记录的方向必须是「降」。
4. **真人专属只归本人**（遍历覆盖表双向校验：别人拿不到、本人必须拿到）。
5. **伤害类型与官网 `effect` 标签一致**（正面清单 + 反面清单，专防「赵云打谋略伤害」回潮）。

发布侧另加两道闸：

- `check-release` §7.7.5 新鲜度清单新增 `conf/campaign/hero-skills.json` 与 `innate-skill-overrides.json`——这两份不是运行时回写，却直接决定每位武将进战场的战法，改了就必须让全部验收报告作废；
- `tools/pack.js` 语言包瘦身从「先全量复制再逐个删」改成**复制时过滤**。宿主删除保护按单次调用累计条数限流（阈值 50，递归删除还展开子文件计数），Electron 45 自带 50+ 个 `.pak`，先拷后删必然以 `SAFE_DELETE_BULK_CONFIRM_REQUIRED` 中途失败；过滤复制一条都不删。

## 7. 合规红线（不可越）

- 战法**名称**来自率土之滨官网公开名录，仅作本地学习与内部对照；**描述文案与本游戏内核数值全部重写**，不是照抄官网数值（官网数值与本内核档位体系不同）。
- 对外发行前必须走 `docs/合规与换皮清单.md` 换皮，审计文件 `license` 字段已写明这一点。
- 不下载、不打包任何官网素材（图标/立绘/页面截图）；本批只落名称与效果范式的结构化描述。

## 8. 复现链

```bash
cd offline
node tools/build-innate-skills.mjs        # 生成 conf/innate-skills.json + hero-skills.json + 审计
node tools/normalize-hero-stats.mjs --dry # 先看会改谁（幂等：已改过则显示 0 处改动）
node tools/normalize-hero-stats.mjs       # 落盘
npm test                                   # 443 条，含本批 5 条
node tools/pack.js && node tools/smoke.js && node tools/smoke.js --packaged
node tools/check-release.js
```

两个脚本都是同源输入 → 同输出，可重复跑；`build-innate-skills.mjs` 的效果签名与 `hero-skills.json` 都做过幂等验证（连跑两次无 diff）。
